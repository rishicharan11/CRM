# Vendor service proposals

For Flight, Accommodation, Visa, Transport and Cruise queries, **Build proposal** opens a table of products matching the registered query requirements. Service and location searches are removed. The Services and Vendors tabs use the same filter, including each product's supplier ownership. The existing table, tabs and form styling remains. Trip continues to use its itinerary builder.

Choose a matching service, select its vendor, then enter the supplier's product details, availability, quote reference, received date, validity and total price in **Test rate**. Multiple selections become alternative options, so their prices are not summed. Pending options can be saved as drafts. Sharing in the existing Communication composer requires every option to have a current quote matching the query's requirements. Expired quotes require reconfirmation. No matching product produces an empty result, including Cruise until cruise products are added to the catalogue.

Vendor services can supply structured `queryProducts`, defined by `ServiceQueryProduct` in Vendor CRM. Flights require ordered flight legs: an outward-only product cannot satisfy a return query. Dates, departure times, cabin, preferred airline, traveller capacity and other registered constraints are checked against product data. Accommodation checks destination, property/room type, dates, rooms, meal plan, star rating and requested property. Visa, Cruise and Transport apply their corresponding requirements. Missing coverage data never implies a match. Older sample queries now have explicit requirements rather than deriving destinations from whatever suppliers happen to exist.

The current Vendor CRM has no live inventory API and its sample catalogue contains general service records without query product coverage. These are not presented as matching flight or accommodation offers. The Bangalore–Dubai return flight, Maldives water villa and Thailand visa examples therefore show **No services or vendors found** until suitable products are registered. No live inventory, routes, availability or prices are fabricated. The Communication composer keeps the application's existing local email behaviour.

`scripts/sync-service-catalog.mjs` refreshes `data/vendor-service-catalog.json` from the sibling `pakages-module/vendor-crm/src/data` before development and production builds. Standalone builds use the checked-in snapshot. Changes made only in the Vendor CRM's in-memory UI are not synced. Saved service proposals and their linked query/customer records persist in this browser's local storage, not a shared backend.

Run `npm run build`, `npm run verify:service-matching`, `npm run verify:service-proposals` and `npm run verify:ui`. Matching checks include positive fixtures for each query type and mismatched requirements. Browser checks first verify the real catalogue's empty results, then inject isolated test product fixtures to exercise selection, quoting and persistence. Set `PREVIEW_URL` and `BROWSER_EXECUTABLE` when using a different local server or installed Chrome.
