# Customer Module component mapping

**Working branch:** `customer-module-mvp1`
**Purpose:** visual component mapping only; no application implementation in this phase.

## Evidence and mapping rules

- Customer scope and behavior: `CUSTOMER-MODULE-SCOPE.md`, then checked against `index.html`, `app.js`, `styles.css`, and `design-system-03.css`.
- Visual reference: local `../pakages-module` checkout at `7c2009e4de3a7cbb117fa66c8bfe0564268ffbb7`, including Booking (`booking-module`), Vendor CRM (`vendor-crm`), Finance (`finance-module`), the integrated `src/App.tsx` shell, and installed `@paryatech/ui` / `@paryatech/design-system` tokens and components. The supplied GitHub URL could not be fetched from this environment; this mapping is pinned to the same local reference revision used by `DESIGN-MIGRATION-AUDIT.md`.
- **Reuse** = retain an existing Customer control/markup and apply the reference component's token and visual recipe. **Adapt** = apply a reference composition to the existing Customer structure, fields, and interactions. **Create** = add only a missing Customer visual recipe on existing UI where the reference has no equivalent component. These labels do not authorize new routes, data, behavior, or duplicate functional components.
- The reference's `@paryatech` components are React. Customer is static HTML/CSS/JavaScript. Directly importing those React components would change the architecture; reuse here means CSS/token/markup guidance unless a framework-independent asset or token is already available.
- Token names below are from the reference design system. Core aliases: `--surface` (white), `--side` (warm raised surface), `--ground` (page), `--ink`, `--ink-2`, `--ink-3` (text), `--line`, `--line-hover` (borders), `--accent` (teal work action), `--pink`, `--pink-soft`, `--pink-line` (selected person/navigation), `--ok`, `--warn`, `--bad`, `--info` with corresponding background/border roles for status, `--radius-sm`, `--radius-md`, `--radius-lg`, `--menuShadow`, `--overlayShadow`, `--space-1` to `--space-5`, and `--font-display`, `--font-sans`, `--font-mono`. Use the semantic role, not a literal color copy.

## Implementation order after approval

1. **Shared first:** verify token aliases and typography, then shell, buttons/icon buttons, fields/selects, search/filter menus, tabs/chips/avatars, sheets/pagination, modal/feedback states. Apply recipes to the existing vanilla controls; avoid creating a second component family.
2. **Shared compositions:** dashboard sheets/cards, notes, notifications/account, global and scoped task tables/forms, customer/query mail workspaces.
3. **Customer-specific visual passes:** inbox channel threads; task/query Kanban; six query forms; proposal catalog and Trip builder; Customer profile/traveller/referral; pipeline/finance; grouped vault, secure upload and review; import; Vendor/Booking entry forms.
